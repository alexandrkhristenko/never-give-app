## Два дефекта на пути входа, оба про молчание

**`/auth/callback` проглатывал отказы.** Маршрут читал только `code`: результат `exchangeCodeForSession` отбрасывался, а параметры `error`/`error_description`, которыми Supabase сообщает об отказе, не читались вовсе. Просроченная ссылка подтверждения, отменённое согласие у провайдера и несовпадение PKCE выглядели отсюда неотличимо от успеха — и все три заканчивались редиректом на `/dashboard`, откуда `requireSessionUser` уводил на `/login`. Человек оказывался у формы входа без единого слова о том, что случилось.

**Сообщение об отказе выбрасывалось в URL.** `/auth/signin` составлял `redirect('/?error=Could not authenticate')`, а `Home()` не принимал `searchParams` и никогда не читал `error`.

Теперь у каждого исхода есть код, а у кода — предложение. Текст лежит в репозитории, а не берётся из параметра: параметр пишет тот, кто составил ссылку, и эхо превратило бы `/?error=<что угодно>` в способ напечатать произвольные слова на нашей странице над нашими же кнопками входа. На это есть E2E, который пытается вывести туда фальшивый номер телефона.

Первая версия набора E2E искала `alert` по всей странице и поймала живую область Next `__next-route-announcer__` — один тест позеленел при лендинге, который ничего не показывал. Тест вхолостую того же класса, что A1 в реестре. Локатор теперь внутри `main`.

## Четырнадцать расхождений в документах

Самое существенное: `data-model` обещал `promises.title` как `varchar(255)`, в схеме — 80, и та же цифра лежит в валидации. В `architecture` §9 абзац стоял **внутри** таблицы, из-за чего три последние переменные окружения не отрисовывались как таблица. README требовал `SUPABASE_SERVICE_ROLE_KEY` для E2E, прямо противореча handover и B1 — первый файл нового человека посылал его добывать самый опасный ключ проекта.

`product-spec` объявляет себя нормативным и при этом требовал 404 там, где отдаётся 200, и называл `private` зарезервированным под экран настроек, который давно существует. Требование 404 снято как требование, а не объявлено дефектом: это следствие потоковой отдачи Next 16, уже записанное решением.

## Два заблокированных пункта, не значившихся нигде

**B10: Google и GitHub не включены в Supabase.** Проверено запросом: `authorize` отвечает `400 provider is not enabled`. Две из трёх кнопок на лендинге уводят человека на страницу с JSON **вне приложения**. Кодом не чинится — `signInWithOAuth` отдаёт исправный URL, отказывает уже эндпоинт Supabase в браузере. Если включать не планируется, кнопки надо убрать.

**B9: Sentry** существовал только как ссылка в пустоту — A5 и known-issues 2.6 отправляли «в раздел B», где его не было.

## Ещё один дефект, найденный воспроизведением

**Онбординг создавал аккаунт в `UTC` и не сообщал об этом.** Скрытое поле с таймзоной заполняется эффектом React, а в HTML стояло `defaultValue="UTC"` — значит отправка, опередившая гидратацию, посылала `UTC`, неотличимо от браузера, который действительно в UTC.

Воспроизведено на проде с задержкой JS-чанков на двадцать секунд: браузер сообщает `America/New_York`, аккаунт создаётся в `UTC`. Граница суток оказывается в 19:00 по местному, вечерняя отметка попадает на «завтра». Это §4.1 спеки — ядро продукта.

Первая гипотеза (React возвращает `defaultValue` при повторном рендере) была опровергнута наблюдением: поле держало значение все 52 опроса. Дело в гидратации, не в рендере.

Регистрацию не отвергаем — значение приходит непрошено, и блокировать её хуже. Но случай перестал быть невидимым: `resolveTimezone` различает «браузер молчал» и «браузер сказал UTC», и онбординг пишет `onboarding.timezone_absent`. Проверено на прод-сборке.

113 юнитов, 45 тестов БД, 40 E2E, `tsc` чист, линтер **0 предупреждений** (было 4: конвенция подчёркивания теперь уважается конфигом, а неиспользуемый `options` убран из деструктуризации по образцу снипетов Supabase), сборка проходит.

## Осталось за владельцем

1. Включить Google и GitHub в Supabase → Authentication → Providers
2. Добавить `https://www.never-give.app/auth/callback` в Redirect URLs
3. Прогнать профиль через отладчики Facebook, X и Telegram — теги и картинка уже проверены на живом домене `www.never-give.app`
4. Завершить свой онбординг: в базе один аккаунт `auth.users` без профиля. Онбординг на проде проверен и работает, см. handover §9
