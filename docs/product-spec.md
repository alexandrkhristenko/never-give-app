# never-give.app — продуктовая спецификация

Версия: MVP. Дата: 2026-08-06.

Этот документ задаёт **семантику продукта**. Всё, что касается расчёта стриков,
видимости и заморозок, считается нормативным: код обязан соответствовать
описанному здесь поведению, а не наоборот.

---

## 1. Что это

Трекер публичной ответственности в 8-битной эстетике. Пользователь публично
обещает делать что-то каждый день, отмечается раз в сутки и накапливает стрик.
Публичная страница профиля превращает обещание в социальное обязательство —
её можно расшарить, и она отдаёт OG-картинку с текущим стриком.

Одна фраза: **пообещал публично → отмечаешься каждый день → не даёшь стрику
сгореть.**

## 2. Границы MVP

**Входит:**

- Регистрация и вход: Google OAuth, GitHub OAuth, email + пароль
- Онбординг: выбор username, первое обещание, видимость, автоопределение таймзоны
- Ровно **одно** активное обещание на пользователя
- Ежедневный чек-ин (одна отметка в сутки по таймзоне пользователя)
- Текущий и лучший стрик
- Заморозки стрика (streak freezes)
- Публичная страница профиля `/<username>`
- OG-картинка для шаринга

**Не входит (зарезервировано, см. [data-model.md](./data-model.md)):**

- Подписки, лента, лидерборд (`followers`)
- Прокачка аватара, очки (`avatar_level` растёт, `total_score`)
- Платный тариф (`is_premium`)
- Недельная периодичность (`cadence = 'weekly'`)
- Несколько обещаний на пользователя
- Архивация обещаний (`status`), заметки к чек-инам (`checkins.note`)

Ограничение «одно обещание» — продуктовое, не техническое: схема допускает
много, UI сознательно показывает первое.

## 3. Пользовательские сценарии

### 3.1. Первый вход

1. Гость открывает `/`, видит лендинг с тремя способами входа.
2. После успешной аутентификации попадает на `/auth/callback`, оттуда — в приложение.
3. Если в БД нет строки `users` с его id — редирект на `/onboarding`.
4. На онбординге заполняет username, текст обещания, видимость. Таймзона
   подставляется скриптом из `Intl.DateTimeFormat().resolvedOptions().timeZone`.
5. При сохранении создаются строка `users` и строка `promises`. Редирект на `/dashboard`.

**Ошибки онбординга показываются в форме, а не проглатываются:**

| Ситуация | Сообщение |
|---|---|
| Username занят | `This username is already taken.` |
| Username не проходит валидацию | `Username must be 3-20 characters: letters, digits, underscore.` |
| Пустое обещание | `Describe what you are committing to.` |
| Прочий сбой БД | `Something went wrong. Please try again.` |

### 3.2. Ежедневный чек-ин

1. Авторизованный пользователь открывает `/dashboard`.
2. Видит текст обещания, текущий стрик, лучший стрик, баланс заморозок.
3. Если сегодня ещё не отмечался — активна кнопка `CHECK IN TODAY`.
4. Если отмечался — кнопка неактивна с текстом `DONE FOR TODAY`.
5. Нажатие создаёт чек-ин на **сегодняшнюю локальную дату** пользователя.
6. Повторное нажатие ничего не ломает: уникальность `(promise_id, local_date)`
   гарантирует ровно одну отметку в сутки.

### 3.3. Публичный профиль

1. Любой посетитель открывает `/<username>`.
2. Видит username, текст обещания, текущий и лучший стрик.
3. Если пользователя нет, или обещание помечено `private` — 404.
4. Метаданные страницы содержат OG-картинку с username, текстом обещания и стриком.

## 4. Правила стрика

Это ядро продукта. Всё описанное ниже реализуется **чистыми функциями** без
обращения к БД и без чтения системного времени внутри, чтобы быть тестируемым.

### 4.1. Локальная дата

Все даты — строки формата `YYYY-MM-DD`, вычисленные в таймзоне пользователя
(`users.timezone`, IANA-идентификатор, по умолчанию `UTC`).

- `today` — текущая локальная дата пользователя
- `yesterday` — `today` минус один день

**Никогда** не используем UTC-дату там, где нужна локальная. Смена суток
происходит по часам пользователя, а не по Гринвичу.

### 4.2. Закрытый день

День считается **закрытым** (covered), если для обещания существует:

- запись в `checkins` на эту дату, **или**
- запись в `streak_freezes` на эту дату.

Множество закрытых дней = объединение этих двух.

### 4.3. Текущий стрик

```
если today закрыт:           якорь = today
иначе если yesterday закрыт: якорь = yesterday
иначе:                       текущий стрик = 0

текущий стрик = длина непрерывной цепочки закрытых дней, заканчивающейся якорем
```

Правило про `yesterday` — это **грация на текущий день**: пока сегодняшний день
не закончился, он не считается пропущенным. Пользователь, отметившийся вчера и
ещё не отметившийся сегодня, видит живой стрик, а не ноль.

### 4.4. Лучший стрик

Длина самой длинной непрерывной цепочки закрытых дней за всю историю обещания.
Текущий стрик всегда `<= лучший стрик`.

### 4.5. Заморозки: начисление

- Начисляются **за длину стрика**: каждые `FREEZE_EARN_INTERVAL = 7` дней.
- Потолок баланса: `MAX_FREEZE_BALANCE = 3`.
- Момент начисления: **успешное создание новой записи чек-ина**. Если после
  вставки текущий стрик кратен 7 и баланс меньше потолка — баланс увеличивается на 1.
- Идемпотентность: повторный чек-ин на ту же дату не создаёт новой строки,
  значит и заморозку не начисляет.

### 4.6. Заморозки: списание

Списание **ленивое** и **автоматическое**: происходит при загрузке дашборда
владельцем, до расчёта отображаемого стрика.

```
закрытые = чек-ины ∪ замороженные дни

если закрытых нет:            ничего не делаем
последний = max(закрытые)
если последний >= yesterday:  ничего не делаем   # завершённых пропусков ещё нет

пропуски = [последний + 1 день .. yesterday]     # завершённые незакрытые дни

если len(пропуски) <= баланс заморозок:
    заморозить каждый день из пропусков; баланс -= len(пропуски)
иначе:
    стрик сгорел; заморозки НЕ тратятся
```

**Правило «всё или ничего»**: если заморозок не хватает, чтобы закрыть весь
разрыв, не тратится ни одной. Частично спасённый стрик всё равно сгорит, а
заморозки лучше сохранить на будущее.

### 4.7. Порядок операций

| Действие | Последовательность |
|---|---|
| Загрузка дашборда | 1. Списать заморозки → 2. Посчитать стрик → 3. Отрисовать |
| Чек-ин | 1. Списать заморозки → 2. Вставить чек-ин → 3. Начислить заморозку, если стрик кратен 7 |
| Публичный профиль | Только чтение. Заморозки **не** списываются |

Публичный профиль не пишет в БД: анонимный посетитель не должен провоцировать
мутации. Следствие — до первого захода владельца публичная страница может
показывать стрик, который на самом деле уже спасён заморозкой или уже сгорел.
Это осознанный компромисс ленивого списания.

### 4.8. Примеры

Везде `today = 2026-08-10`, `yesterday = 2026-08-09`.

| Чек-ины | Заморожено | Баланс | Текущий | Лучший | Комментарий |
|---|---|---|---|---|---|
| — | — | 0 | 0 | 0 | Ничего не было |
| `08-10` | — | 0 | 1 | 1 | Отметился сегодня |
| `08-09` | — | 0 | 1 | 1 | Грация: сегодня ещё не пропущен |
| `08-08` | — | 0 | 0 | 1 | `08-09` пропущен, заморозок нет |
| `08-08` | `08-09` | 1→0 | 2 | 2 | Пропуск закрыт заморозкой |
| `08-06,08-07,08-08` | — | 5 | 0 | 3 | Баланс не может превышать 3, см. 4.5 |
| `08-05..08-08` | — | 1 | 0 | 4 | Разрыв 1 день (`08-09`) → закрывается |
| `08-01..08-05` | — | 2 | 0 | 5 | Разрыв 4 дня > 2 → сгорел, заморозки целы |
| `08-04..08-10` | — | 0→1 | 7 | 7 | 7 дней подряд → +1 заморозка |

## 5. Видимость

Поле `promises.visibility`:

| Значение | Публичная страница | В онбординге |
|---|---|---|
| `public` | Доступна всем | Предлагается (по умолчанию) |
| `unlisted` | Доступна по прямой ссылке, не индексируется | Предлагается |
| `private` | 404 для всех, кроме владельца на его дашборде | **Не предлагается в MVP** |

`private` обрабатывается кодом и политиками БД, но в онбординге не выбирается —
поле зарезервировано под будущий экран настроек.

Для `unlisted` страница отдаёт `robots: { index: false, follow: false }`.

## 6. Валидация username

- Длина 3–20 символов
- Разрешены: латинские буквы, цифры, подчёркивание (`^[a-zA-Z0-9_]{3,20}$`)
- Регистронезависимая уникальность: `Player1` и `player1` — один и тот же занятый ник
- Хранится в том регистре, который ввёл пользователь; сравнивается в нижнем
- Зарезервированные значения запрещены: `admin`, `api`, `auth`, `dashboard`,
  `login`, `onboarding`, `settings`, `about`, `help`, `support`, `null`,
  `undefined`, `www`

Зарезервированный список нужен, потому что профиль живёт в корне (`/<username>`)
и конкурирует за путь с системными роутами.

## 7. Что считается готовым MVP

- [ ] Пользователь регистрируется любым из трёх способов и доходит до дашборда
- [ ] Онбординг показывает внятную ошибку на занятом username
- [ ] Чек-ин работает и не дублируется
- [ ] Стрик считается по таймзоне пользователя, а не по UTC
- [ ] Заморозка автоматически закрывает пропущенный день
- [ ] Публичный профиль открывается и отдаёт OG-картинку фирменным шрифтом
- [ ] `private` профиль отдаёт 404
- [ ] RLS включена, чужие данные недоступны на уровне БД
- [ ] Миграции лежат в репозитории, схема воспроизводима на чистой БД
- [ ] `npm test` и `npm run test:e2e` зелёные, `npm run build` проходит
