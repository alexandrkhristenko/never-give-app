## 1. Переменные окружения

Двух переменных нет, и обе нужны.

| Переменная | Куда | Зачем |
|---|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` | **`.env.test.local`** | Сквозной E2E создаёт тестового пользователя через Admin API |

**Не кладите сервисный ключ в `.env.local`.** Всё оттуда попадает в серверный
рантайм приложения, а этой роли там быть не должно: она обходит RLS. Файл
`.env.test.local` уже в `.gitignore`.

## 2. Прогнать сквозной E2E

`e2e/streak.spec.ts` **ни разу не запускался** — только вычитан.

```bash
npm run test:e2e
```

Механика заморозок при этом **уже покрыта** — отдельным набором, который не
требует сервисного ключа, потому что засевает данные напрямую через
`DATABASE_URL`:

```bash
npm run test:db
```

Десять случаев прогоняют настоящие функции DAL против настоящей базы: списание,
правило «всё или нет», идемпотентность, неприкосновенность текущего дня,
начисление на седьмой день, потолок и вызов, который тратит и зарабатывает
одновременно. Вместе с ними проверяются блокировка `FOR UPDATE`, колоночные
гранты роли `authenticated` и политики на `streak_freezes` — то, чего юнит-тесты
чистой функции не достают.

Занятый username **покрыт** — в `npm run test:db`, где второй владелец имени
засевается напрямую. Пункт product-spec §7 закрыт.

Этот же набор поймал два дефекта, которые не видны без живой базы:

- **онбординг был сломан для всех.** Сужение INSERT-грантов в миграции 0002
  верно по замыслу, но Drizzle перечисляет в INSERT все колонки таблицы, а
  Postgres проверяет привилегию на каждую **названную**, даже со значением по
  умолчанию. Регистрация падала с `permission denied`. Миграция 0003 разделяет
  ответственность: грант решает, какие колонки можно называть, политика —
  какие значения допустимы;
- **занятый ник сообщался как неизвестный сбой.** Drizzle оборачивает ошибку
  драйвера и кладёт оригинал в `cause`, поэтому код и имя ограничения читались
  на обёртке и никогда не совпадали.

## 5. Известный долг

Не дефекты, а осознанные решения либо мелочи, зафиксированные ревью:

- **Публичный профиль отдаёт HTTP 200** с содержимым «не найдено». Это следствие
  потоковой отдачи динамических маршрутов в Next 16; фреймворк компенсирует
  тегом `<meta name="robots" content="noindex">`, он на странице есть.
  Проверено: удаление `loading.tsx` статус не меняет.
- **Форма входа не покрыта компонентными тестами.** Vitest здесь настроен только
  на Node; DOM-стек — отдельное решение.
- **`check_email` не привязан к режиму:** переключение тумблера во время
  отправки регистрации покажет «REGISTRATION SUCCESSFUL» в режиме входа.
  Безвредно — аккаунт действительно создан.
- **`timestamp` без часового пояса** в схеме. Сейчас не видно наружу, но станет
  ловушкой для любой фичи, читающей `created_at` в JS. Лечится `timestamptz`.
- **Прерванный прогон E2E** может оставить пользователя `e2e-*@never-give.test`
  в `auth.users`. Чистится по префиксу адреса.
- **`validation.test.ts` проверяет 5 из 13** зарезервированных имён. Полезнее не
  дописывать остальные восемь, а утверждать, что список покрывает все сегменты
  верхнего уровня в `src/app/` — портится именно это соответствие.
