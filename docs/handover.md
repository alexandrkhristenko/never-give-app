## 2. Прогнать сквозной E2E

`e2e/streak.spec.ts` **ни разу не запускался** — только вычитан. Это самый
крупный пробел в проверке.

```bash
npm run test:e2e
```

Механика заморозок при этом всё равно останется без сквозного покрытия: тест
отмечается один раз и проверяет стрик 1. Чтобы закрыть пункт «Заморозка
автоматически закрывает пропущенный день» из [product-spec §7](./product-spec.md),
нужен тест, который засевает чек-ин задним числом и баланс заморозок, а затем
проверяет, что пропуск закрылся. Сегодня эта механика подтверждена только
юнит-тестами чистой логики и рассуждением о блокировках.

Ещё не покрыт занятый username: тест с таким названием проверяет
**зарезервированное** имя. Нужен второй засеянный пользователь.

## 5. Известный долг

Не дефекты, а осознанные решения либо мелочи, зафиксированные ревью:

- **Публичный профиль отдаёт HTTP 200** с содержимым «не найдено». Это следствие
  потоковой отдачи динамических маршрутов в Next 16; фреймворк компенсирует
  тегом `<meta name="robots" content="noindex">`, он на странице есть.
  Проверено: удаление `loading.tsx` статус не меняет.
- **Форма входа не покрыта компонентными тестами.** Vitest здесь настроен только
  на Node; DOM-стек — отдельное решение.
- **`check_email` не привязан к режиму:** переключение тумблера во время
  отправки регистрации покажет «REGISTRATION SUCCESSFUL» в режиме входа.
  Безвредно — аккаунт действительно создан.
- **`timestamp` без часового пояса** в схеме. Сейчас не видно наружу, но станет
  ловушкой для любой фичи, читающей `created_at` в JS. Лечится `timestamptz`.
- **Прерванный прогон E2E** может оставить пользователя `e2e-*@never-give.test`
  в `auth.users`. Чистится по префиксу адреса.
- **`validation.test.ts` проверяет 5 из 13** зарезервированных имён. Полезнее не
  дописывать остальные восемь, а утверждать, что список покрывает все сегменты
  верхнего уровня в `src/app/` — портится именно это соответствие.
