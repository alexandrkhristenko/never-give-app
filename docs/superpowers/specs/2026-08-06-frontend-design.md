## 1. Что не так с текущим фронтендом

Перечень нужен, чтобы решения ниже читались как ответы, а не как вкусовщина.
Дефекты бизнес-логики сюда не входят — они в
[known-issues.md](../../known-issues.md).

### 1.1. NES.css выигрывает у Tailwind в каскаде

`node_modules/nes.css/css/nes.min.css` не содержит ни одного `@layer`.
Tailwind 4 объявляет `@layer theme, base, components, utilities` и помещает туда
всё своё. По правилам каскада **нелейерные правила выигрывают у лейерных**
независимо от специфичности и порядка подключения.

Следствия:

- `.nes-btn` задаёт `color: #212529; background-color: #fff` и перебивает любую
  Tailwind-утилиту. Тёмная тема на кнопках недостижима.
- NES.css содержит **Bootstrap Reboot v4.1.3** целиком. Он подключается после
  Tailwind и переопределяет его preflight, включая `html { font-family: sans-serif }`.
- NES.css подменяет системный курсор base64-картинкой на `html` и на `.nes-btn`.

### 1.2. Тёмная тема объявлена, но не работает

`globals.css` содержит блок `@media (prefers-color-scheme: dark)`, а все страницы
хардкодят `bg-[#212529]` и белые панели. Блок — мёртвый код.

### 1.3. Нет слоя компонентов

Каталога `src/components` не существует. Шапка, панель, блок статов скопированы
между `dashboard/page.tsx` и `[username]/page.tsx` — та же болезнь, что и с
продублированным `calculateStreak` (known-issues 1.3), только в разметке.

### 1.4. Адаптив не покрывает 375–767px

Перестроение задано как `flex-col md:flex-row`, то есть на 768px. Три колонки
статов между 375 и 767px стоят в ряд, места на них нет.

`.nes-container` по умолчанию — `padding: 1.5rem 2rem` плюс `border-width: 4px`.
На вьюпорте 320px под контент остаётся 216px.

`transform: scale(2.5)` на аватаре не меняет занимаемое место, поэтому соседние
блоки о его размере не знают.

### 1.5. Отсутствуют служебные состояния

Ни `loading.tsx`, ни `error.tsx`, ни `not-found.tsx` ни на одном роуте, хотя
architecture.md §3 их описывает. Пустые состояния (день первый, сгоревший стрик,
отсутствующее обещание) не спроектированы.

### 1.6. Продуктовые пробелы

- **История не отрисовывается.** 365 чек-инов загружаются, показывается одно число.
- **Баланс заморозок не показан нигде**, хотя product-spec §4.5 его требует.
- **На публичном профиле нет кнопки «поделиться»** — при том что шаринг заявлен
  единственным каналом дистрибуции.
- **Нет выхода из аккаунта.**
- **Лендинг не объясняет механику** — три кнопки входа без единого слова о продукте.
- **`Lvl 1` показывается, механики прокачки нет** (known-issues 1.14).

### 1.7. Доступность

- Анимация `is-moving` без учёта `prefers-reduced-motion`.
- Кнопка чек-ина после отметки остаётся `disabled`: выпадает из табуляции и не
  сообщает причину.
- Подмена курсора ломает системные настройки размера и контраста указателя.
- Логотип размечен как `h1`, содержательный заголовок страницы — как `h2`.

## 2. Слои стилей

### 2.1. Порядок каскада

`globals.css` перестраивается так, чтобы NES.css оказался **под** нашими слоями:

```css
@layer theme, base, nes, components, utilities;

@import "tailwindcss";
@import "nes.css/css/nes.min.css" layer(nes);
@import "./nes-theme.css" layer(components);
```

После этого любая Tailwind-утилита и любой наш класс выигрывают у NES.css без
единого `!important`.

Порядок объявления слоя проверяется при реализации: `@import "tailwindcss"`
объявляет свои слои сам, и явный `@layer` перед импортом должен зафиксировать
итоговый порядок. Критерий приёмки — `bg-[--color-panel]` на элементе с классом
`nes-btn` побеждает.

### 2.2. `nes-theme.css`

Единственное место, где переопределяется NES.css. Что в нём:

| Селектор | Что меняем | Зачем |
|---|---|---|
| `.nes-container` | `padding` на токен, `border-color` на токен | §1.4, тёмная тема |
| `.nes-btn`, варианты | цвета на токены, `min-height: 44px` | §1.1, цель нажатия |
| `.nes-input`, `.nes-select`, `.nes-field` | цвета на токены | тёмная тема |
| `html`, `.nes-btn` | `cursor: auto` / `pointer` | §1.7 |
| `:focus-visible` | обводка 3px, `outline-offset: 2px` | §7.5 |

Классы `nes-*` за пределами этого файла и компонентов `src/components/ui/`
не используются.

### 2.3. Токены

Объявляются в `@theme`. Токены **семантические**, не палитра.

| Токен | Роль |
|---|---|
| `--color-bg` | фон страницы |
| `--color-panel` | фон панели |
| `--color-ink` | основной текст |
| `--color-ink-muted` | подписи |
| `--color-edge` | рамка |
| `--color-streak` | число текущего стрика |
| `--color-freeze` | заморозка |
| `--color-miss` | пропущенный день |
| `--space-1` … `--space-8` | шаг 4px, пиксельная сетка |

Литералы `#212529`, `text-red-500`, `text-gray-500` из страниц и компонентов
исчезают полностью.

`--color-ink-muted` получает **разные значения в светлой и тёмной теме**:
одно значение не проходит AA в обеих.

### 2.4. Переключение темы

Механизм: **cookie + атрибут `data-theme` на `<html>`**.

```
корневой layout читает cookies() -> ставит data-theme в серверном HTML
CSS:  :root                                  светлые значения
      @media (prefers-color-scheme: dark)    тёмные значения
      :root[data-theme="dark"]               тёмные значения
      :root[data-theme="light"]              светлые значения
```

Медиазапрос обслуживает первый визит без куки. Атрибут перебивает его в обе
стороны — пользователь с системной тёмной темой может выбрать светлую.

Мигания при загрузке нет, блокирующий inline-скрипт не нужен. Корневой layout
становится динамическим; это допустимо: Cache Components выключены
(architecture.md §6), а обе основные страницы и так ходят в БД на каждый запрос.

Отвергнутые варианты: `localStorage` с блокирующим скриптом (требует
`dangerouslySetInnerHTML` до первой отрисовки — приём, который из онбординга
как раз убирается); только `prefers-color-scheme` (не даёт переключателя).

### 2.5. Шрифты

| Где | Шрифт |
|---|---|
| Заголовки, числа, кнопки, подписи-капсы, текст обещания | `Press Start 2P` |
| Мелкий текст: подсказки, ошибки, объяснения на лендинге | `ui-monospace, SFMono-Regular, Menlo, monospace` |

Press Start 2P на 12px нечитаем. Системный моностек не стоит ни байта трафика.

Из `next/font` убирается сабсет `cyrillic`: интерфейс английский (§10).

Press Start 2P — моноширинный, ширина глифа ровно `1em`. Это делает
переполнение вычислимым, чем §5 и пользуется.

## 3. Структура компонентов

```
src/components/
  ui/                     примитивы, о домене не знают
    panel.tsx             обёртка .nes-container: tone, title
    pixel-button.tsx      обёртка .nes-btn: variant, size, pending
    field.tsx             label + input + ошибка + подсказка
    theme-toggle.tsx      'use client'
  streak/
    streak-chain.tsx      лента дней
    streak-stats.tsx      current / best
    freeze-meter.tsx      остаток заморозок
    avatar-stage.tsx      спрайт по стадии стрика
  layout/
    app-header.tsx
    app-menu.tsx          'use client'
  share/
    share-bar.tsx         'use client'
```

### 3.1. Чистый слой представления

```
src/lib/view/
  chain.ts   { today, checkins, freezes, days } -> Cell[]
  stage.ts   currentStreak -> Stage
```

Обе функции **чистые**: без импортов из БД, без чтения системного времени.
`today` передаётся аргументом. Требования те же, что к `src/lib/streak.ts`
и `src/lib/dates.ts` (architecture.md §3), и покрываются Vitest так же.

```ts
type Cell = { date: string; state: 'checked' | 'frozen' | 'missed' | 'empty' | 'future' }
type Stage = 'dormant' | 'walking' | 'running' | 'blazing' | 'crowned'
```

Дашборд, публичный профиль и OG-картинка строят цепочку из **одной** функции.
Иначе повторится история с продублированным `calculateStreak`.

### 3.2. Границы клиента и сервера

Серверные: страницы, панели, статы, цепочка, аватар, шапка.

Клиентских островов ровно пять:

| Компонент | Почему клиент |
|---|---|
| `theme-toggle` | запись куки, `router.refresh()` |
| `app-menu` | раскрытие, закрытие по `Esc` |
| `share-bar` | `navigator.share`, буфер обмена |
| `checkin-form` | `useActionState`: pending, ошибка, `+1 FREEZE` |
| `onboarding-form` | таймзона, проверка username (задача 11 плана) |

Анимация появления нового звена цепочки делается **чистым CSS** на серверно
отрисованной ячейке. Клиентское состояние для неё не заводится.

## 4. Экраны

### 4.1. Общее правило раскладки

Дашборд и публичный профиль — **одна центрированная колонка `max-w-[42rem]` на
всех ширинах**. Перестроений «несколько колонок → одна» нет.

Это решение, а не упрощение: перестроение на `md` оставляет непроверенным
диапазон 375–767px (§1.4), а показывать во второй колонке нечего — у продукта
одно действие. Меняются только размер шрифта и длина цепочки.

Брейкпоинты: `sm` (640) и `lg` (1024). `md` не используется.

### 4.2. Дашборд

```
базовый (320-639)                 десктоп (1024+)
+---------------------+           +---------------------------------+
| never-give  [*] [=] |           | never-give.app  @player1 [*] [=]|
+---------------------+           +---------------------------------+
| ACTIVE QUEST        |           | ACTIVE QUEST                    |
|                     |           |                                 |
| "Code every day"    |           |     "Code every day"            |
|                     |           |                                 |
|      [avatar]       |           |          [avatar]               |
|                     |           |                                 |
|    17       23      |           |      17            23           |
|  CURRENT   BEST     |           |    CURRENT        BEST          |
|                     |           |                                 |
| [ CHECK IN TODAY ]  |           |     [  CHECK IN TODAY  ]        |
|                     |           |                                 |
| ####@##_########### |           | ##############@##_############# |
| FREEZES  * * -      |           | FREEZES  * * -                  |
+---------------------+           +---------------------------------+
| view public profile |           | view public profile             |
+---------------------+           +---------------------------------+
     14 дней                              30 дней
```

Порядок блоков одинаков на всех ширинах. Кнопка чек-ина попадает в первый экран
на 320px без прокрутки.

### 4.3. Публичный профиль

Те же компоненты, другая композиция:

```
@player1
is committing to:
"Code every day"
[avatar]
   17        23
 CURRENT    BEST
####@##_###########
since 2026-07-11
[ COPY LINK ] [ X ] [ TG ]
[ START YOUR OWN QUEST ]
```

Два отличия от дашборда, оба намеренные:

- **Кнопки чек-ина нет** — профиль чужой.
- **Остаток заморозок не показывается.** Замороженные дни в цепочке видны — это
  часть честной летописи. Остаток баланса — тактическая информация владельца.

### 4.4. Лендинг

```
HERO           логотип, одна фраза, три кнопки входа
HOW IT WORKS   три карточки: promise / check in / don't break it
FREEZES        мини-цепочка, где заморозка закрывает разрыв,
               и правило «всё или ничего» одним предложением
DEMO           статичная цепочка на 30 дней
FOOTER
```

Заморозки выносятся в отдельный блок сознательно: это единственная механика,
отличающая продукт от соседних трекеров, и объяснять её надо до регистрации.

Кнопка Google перестаёт быть `is-error`: красный в системе означает ошибку.
Обе OAuth-кнопки нейтральные, `is-primary` остаётся у email.

### 4.5. Логин и онбординг

**Логин** — панель с переключением sign in / sign up, ошибки под полями,
состояние ожидания на кнопке.

**Онбординг** остаётся одним экраном с тремя полями. Добавляется:

- живая проверка занятости username;
- предпросмотр `never-give.app/<username>`;
- счётчик символов обещания (лимит 80, см. §5.3);
- показ ошибок из product-spec §3.1 (визуальная часть; логика — задача 11 плана).

Селект видимости предлагает `public` и `unlisted`. `private` не предлагается —
product-spec §5.

### 4.6. Служебные состояния

| Файл | Содержимое |
|---|---|
| `dashboard/loading.tsx` | скелет панели пиксельными блоками |
| `[username]/loading.tsx` | то же |
| `dashboard/error.tsx` | проп **`retry`**, не `reset` — Next 16 |
| `[username]/not-found.tsx` | `NO SUCH PLAYER` + переход на лендинг |
| `app/not-found.tsx` | глобальная 404 |

Пустые состояния дашборда:

| Условие | Что показываем |
|---|---|
| чек-инов нет | цепочка из пустых клеток, `your chain starts today` |
| `current = 0`, `best > 0` | `your chain broke at {best} days. start again.` |
| обещания нет | панель с призывом завести обещание, без `undefined` в заголовке |

## 5. Адаптивность

### 5.1. Цепочка

CSS-grid: `grid-template-columns: repeat(var(--chain-n), minmax(0, 1fr))`,
`aspect-ratio: 1` на ячейке.

Сервер всегда отрисовывает 30 ячеек. **Ниже `sm` (640px)** первые 16 скрываются
правилом `:nth-child(-n+16) { display: none }`, а `--chain-n` равен 14; от `sm`
и выше — 30. Замера ширины из JS нет, значит нет и рассинхрона гидрации.

Расчёт стороны ячейки:

| | 320px | 1024px |
|---|---|---|
| ширина колонки | 320px (вьюпорт) | 672px (`max-w-[42rem]`) |
| минус поля страницы (16px × 2) | 288px | не применяются |
| минус рамка панели (4px × 2) | 280px | 664px |
| минус паддинг панели | 248px (`1rem` × 2) | 600px (`2rem` × 2) |
| ячеек | 14 | 30 |
| зазор | 2px | 4px |
| **сторона ячейки** | **~15.8px** | **~15.9px** |

Квадрат получается одного размера на обеих ширинах: цепочка выглядит одинаково,
меняется только её длина.

248px в первой колонке — уже с переопределением паддинга (§5.2).

### 5.2. Паддинг панели

`.nes-container` переопределяется: `padding: 1rem` в базе, `1.5rem 2rem` от `sm`.
Без этого на 320px под контент остаётся 216px (§1.4).

### 5.3. Типографика

| Элемент | Размер |
|---|---|
| число стрика | `clamp(1.75rem, 10vw, 3.5rem)` |
| текст обещания | `clamp(0.75rem, 3.5vw, 1.25rem)` |

На 320px число — 32px, трёхзначное «365» занимает 96px при доступных 116px.
Запас есть и для четырёхзначного.

Текст обещания получает `text-wrap: balance` и `overflow-wrap: anywhere`.

**Длина обещания ограничивается 80 символами** на трёх уровнях: ограничение в
схеме БД, `maxLength` на инпуте, счётчик в форме. Сейчас предела нет нигде, и
одна длинная фраза разносит вёрстку.

### 5.4. Аватар

`transform: scale(2.5)` убирается — трансформация не меняет занимаемое место,
поэтому соседи о размере спрайта не знают (§1.4).

Вместо неё обёртка фиксированного размера: 64px в базе, 96px от `sm`,
`image-rendering: pixelated` внутри.

Стадия приходит из `stage.ts`. Спрайт **один** (`nes-mario`), меняются слои
эффектов:

| Стрик | Стадия | Оформление |
|---|---|---|
| 0 | `dormant` | приглушённый, обесцвеченный |
| 1–6 | `walking` | обычный |
| 7–29 | `running` | `is-moving` |
| 30–99 | `blazing` | + пиксельная аура через `box-shadow` |
| 100+ | `crowned` | + корона |

Подпись `Lvl {avatar_level}` убирается: механики прокачки нет и в MVP не будет
(known-issues 1.14). Под спрайтом — расстояние до следующей стадии.

### 5.5. Обязательные правила

- Горизонтальной прокрутки у `body` нет ни на одной ширине.
- `min-w-0` на каждом grid/flex-потомке с текстом: без этого моноширинный шрифт
  распирает колонку изнутри.
- Минимальная цель нажатия 44px. У `.nes-btn` паддинг `6px 8px` — переопределяется.
- Фиксированного позиционирования нет нигде, поэтому работы с safe-area на iOS
  не требуется.

## 6. Поведение чек-ина

### 6.1. Два состояния, две разметки

Кнопка с атрибутом `disabled` заменяется на разную разметку:

```
не отмечен:   <button>CHECK IN TODAY</button>

отмечен:      <p role="status">
                DONE FOR TODAY
                next check-in after midnight (Europe/Kyiv)
              </p>
```

Действия нет — нет и кнопки. Проблема выпадения из табуляции исчезает вместе
с элементом.

Таймзона в подписи стоит намеренно: граница суток считается по `users.timezone`
(product-spec §4.1). Формулировка «after midnight» выбрана вместо счётчика часов
потому, что посчитанное на сервере число протухает на экране до следующей
ревалидации, а «после полуночи» верно всегда.

### 6.2. Состояние действия

```ts
type CheckInState =
  | { status: 'idle' }
  | { status: 'ok'; earnedFreeze: boolean }
  | { status: 'error'; message: string }
```

`checkin-form` читает его через `useActionState`. Во время ожидания кнопка
получает `aria-busy` и текст ожидания. `earnedFreeze: true` рождает бейдж
`+1 FREEZE` с `role="status"`.

Начисление заморозки происходит по правилу product-spec §4.5 — фронтенд только
отображает результат, вычисленный на сервере.

### 6.3. Анимация нового звена

После `revalidatePath` сервер перерисовывает ячейку сегодняшнего дня. Браузер
проигрывает CSS-анимацию появления один раз при монтировании нового узла.
Клиентского состояния для этого не требуется.

Под `prefers-reduced-motion: reduce` анимация не проигрывается, ячейка просто
появляется.

## 7. Доступность

### 7.1. Движение

Один глобальный блок `@media (prefers-reduced-motion: reduce)` гасит: `is-moving`
у аватара, вспышку нового звена, пульсацию ауры, мерцание скелетонов.

### 7.2. Цепочка

```html
<ol role="img" aria-label="Last 30 days: 17 day streak, 1 day frozen, 1 day missed">
```

Ячейки внутри — `aria-hidden`. Скринридер получает вывод, а не тридцать
одинаковых элементов.

### 7.3. Курсор

NES.css подменяет системный курсор base64-картинкой на `html` и `.nes-btn`.
Это ломает системные настройки размера и контраста указателя. В `nes-theme.css`
курсор возвращается к `auto` / `pointer`.

### 7.4. Контраст

Каждая пара токенов проверяется на WCAG AA при реализации: 4.5:1 для обычного
текста, 3:1 для крупного.

Известные кандидаты на провал: `text-gray-500` на тёмной панели и `is-error`
(`#e76e55`) с белым текстом. Поэтому `--color-ink-muted` получает разные
значения по темам, а варианты кнопок перекрашиваются на токены.

### 7.5. Фокус

`:focus-visible` — пиксельная обводка 3px, `outline-offset: 2px`. Проверяется на
всех интерактивных элементах, включая переключатель темы и пункты меню.

### 7.6. Заголовки

Логотип в шапке перестаёт быть `h1`.

| Страница | `h1` |
|---|---|
| Дашборд | текст обещания |
| Публичный профиль | ник |
| Лендинг | название продукта |

### 7.7. Формы

Ошибки логина и онбординга: `aria-invalid` на поле, `aria-describedby` на
сообщение, `role="alert"` для озвучивания. Декоративные `nes-icon` получают
`aria-hidden`.
